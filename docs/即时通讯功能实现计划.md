# 在线沟通 & 消息中心 — 实现计划

## 一、需求概述

| 入口 | 位置 | 说明 |
|------|------|------|
| 在线沟通 | 职位搜索页 `JobSearch.vue` 职位卡片底部 | 学生点击后进入与该职位所属企业HR的聊天窗口 |
| 与HR直聊 | 职位详情页 `JobDetail.vue` 右侧操作卡片 | 同上 |
| 在线沟通 | 收藏页 `Favorites.vue` 收藏列表 | 同上 |
| 消息中心 | 导航栏通知铃铛 `App.vue` | 显示未读消息数角标，点击进入消息列表页 |
| HR工作台 | 企业端 `HRDashboard.vue` | HR 查看并回复学生消息 |

**核心功能：**
- 学生与HR可以双方主动发起对话
- 实时收发消息（WebSocket）
- 未读消息角标提醒
- 系统通知（投递状态变更、面试通知等）

---

## 二、技术方案

### 推荐：WebSocket + REST API 混合方案

| 层面 | 方案 | 理由 |
|------|------|------|
| 实时通信 | Spring WebSocket + STOMP 协议 | Spring Boot 原生支持，与现有技术栈一致 |
| 消息持久化 | MySQL `t_message` 表 | 已有表结构，简单可靠 |
| 消息推送 | Redis Pub/Sub（可选，单实例可跳过） | 微服务间消息同步；单实例部署暂不需要 |
| 前端连接 | SockJS + STOMP.js | 兼容性好，自动降级 |
| 系统通知 | REST API 轮询 + WebSocket 推送 | 投递/面试状态变更通过后端推送 |

### 为什么不用纯轮询？
- 消息实时性差，用户体验不好
- 频繁请求浪费带宽和服务资源

### 为什么不用第三方 IM SDK（融云/环信）？
- 增加外部依赖和费用
- 数据不在自己手里，不利于后续扩展
- 本项目消息模型简单（一对一私聊），自研成本可控

## 三、数据库设计

### 3.1 会话表 `t_conversation`

```sql
CREATE TABLE t_conversation (
  id BIGINT NOT NULL AUTO_INCREMENT,
  student_id BIGINT NOT NULL COMMENT '学生用户ID',
  hr_id BIGINT NOT NULL COMMENT 'HR用户ID',
  job_id BIGINT COMMENT '关联职位ID（可选）',
  last_message VARCHAR(200) DEFAULT NULL COMMENT '最后一条消息摘要',
  last_time DATETIME DEFAULT NULL COMMENT '最后消息时间',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_student_hr_job (student_id, hr_id, job_id),
  KEY idx_student (student_id),
  KEY idx_hr (hr_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='聊天会话表';
```

### 3.2 消息表 `t_message`（替换现有简单结构）

```sql
CREATE TABLE t_message (
  id BIGINT NOT NULL AUTO_INCREMENT,
  conversation_id BIGINT NOT NULL COMMENT '关联会话ID',
  from_user_id BIGINT NOT NULL COMMENT '发送者ID',
  to_user_id BIGINT NOT NULL COMMENT '接收者ID',
  content TEXT NOT NULL COMMENT '消息内容',
  msg_type TINYINT DEFAULT 1 COMMENT '消息类型：1-文本 2-图片 3-系统通知',
  is_read TINYINT DEFAULT 0 COMMENT '已读状态：0-未读 1-已读',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_conversation (conversation_id),
  KEY idx_to_user (to_user_id),
  KEY idx_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='聊天消息表';
```

### 3.3 系统通知表 `t_notification`

```sql
CREATE TABLE t_notification (
  id BIGINT NOT NULL AUTO_INCREMENT,
  user_id BIGINT NOT NULL COMMENT '接收者ID',
  title VARCHAR(100) NOT NULL COMMENT '通知标题',
  content TEXT COMMENT '通知内容',
  noti_type TINYINT DEFAULT 1 COMMENT '类型：1-投递通知 2-面试通知 3-系统公告',
  related_id BIGINT DEFAULT NULL COMMENT '关联ID（投递ID/面试ID等）',
  is_read TINYINT DEFAULT 0 COMMENT '已读状态：0-未读 1-已读',
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_user (user_id),
  KEY idx_is_read (is_read)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统通知表';
```

## 四、后端架构

### 4.1 服务归属：复用 application-service

消息功能放入现有 `application-service`，理由：
- 该服务已负责投递/简历，消息与投递流程紧密关联
- 避免新增微服务增加运维复杂度
- 已有 MySQL、Feign、Knife4j 等完整基础设施

### 4.2 新增依赖

`application-service/pom.xml` 添加：
```xml
<!-- WebSocket -->

    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-websocket</artifactId>
</dependency>
```

### 4.4 API 接口设计

#### 消息相关

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/message/conversation` | 创建/获取会话（根据 studentId + hrId + jobId） |
| GET | `/api/message/conversations` | 获取当前用户的会话列表 |
| GET | `/api/message/history/{conversationId}` | 获取会话历史消息（分页） |
| POST | `/api/message/send` | 发送消息（REST 备用，主要走 WebSocket） |
| GET | `/api/message/unread-count` | 获取未读消息总数 |

#### 通知相关

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/message/notifications` | 获取通知列表（分页） |
| PUT | `/api/message/notification/read/{id}` | 标记单条已读 |
| PUT | `/api/message/notifications/read-all` | 全部标记已读 |
| GET | `/api/message/notification/unread-count` | 获取未读通知数 |

#### WebSocket 端点

| 端点 | 说明 |
|------|------|
| `/ws` | STOMP 端点（SockJS 升级） |
| `/topic/messages/{userId}` | 用户私聊消息订阅地址 |
| `/topic/notifications/{userId}` | 系统通知订阅地址 |
| `/app/chat.send` | 发送消息（STOMP） |

### 4.5 网关配置

`gateway-service` 的 `application.yml` 添加路由：
```yaml
- id: message-route
  uri: lb://application-service
  predicates:
    - Path=/api/message/**,/ws/**
```

`AuthFilter.java` 白名单添加：
```java
"/api/message/**"
```

## 六、实现顺序（分阶段）

### 第一阶段：基础消息功能（核心）

1. **数据库**：执行建表 SQL（t_conversation、t_message、t_notification）
2. **后端 Entity/Mapper**：创建实体类和 Mapper 接口
3. **后端 Service/Controller**：实现会话管理、消息收发、通知 CRUD
4. **后端 WebSocket**：配置 WebSocket + STOMP，实现消息实时推送
5. **网关配置**：添加路由和白名单
6. **前端 API**：封装 message.js
7. **前端 ChatRoom**：实现聊天窗口页面
8. **前端入口改造**：各页面"在线沟通"/"与HR直聊"按钮接入

### 第二阶段：消息中心

9. **前端 MessageCenter**：实现消息中心页面（会话列表 + 通知列表）
10. **前端 App.vue**：通知铃铛接入未读角标，跳转消息中心
11. **系统通知**：投递状态变更、面试通知自动创建通知记录

### 第三阶段：HR端

12. **HRDashboard**：添加消息模块，HR可查看会话列表并回复
13. **HR消息收发**：通过 WebSocket 实时接收和发送学生消息

## 七、需要确认的问题

| # | 问题 | 建议 |
|---|------|------|
| 1 | 消息是否需要支持图片/文件发送？ | 第一阶段仅支持文本，后续扩展 |
| 2 | 是否需要消息已读/未读回显？ | 第一阶段支持已读状态，不显示"对方已读" |
| 3 | 聊天记录是否需要持久化？ | 是，所有消息存 MySQL，支持历史记录 |
| 4 | 是否需要消息漫游（多设备同步）？ | 第一阶段不需要，单设备登录 |
